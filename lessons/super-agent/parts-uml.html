#结论依据
1五个 Part 是同一事务内的分工，不是五个服务：共享同一份 EngineOptions 与同一个 repoengine.ts:31-38
2唯一事务门在 Engine：27 个 public 方法中 26 个是 repo.atomic(() ⇒ part.…())，例外是只读 candidate()；Part 自己从不开启事务engine.ts:48 起、:90
3基类是工具箱不是模板方法：无抽象方法，子类 public API 数量 1 / 11 / 18 / 7 / 3part.ts:24-79
4跨聚合写必须委托兄弟 Part：Ticket 聚合只有一个写者，靠代码结构而非运行时检查保证part.ts:20-23 注释 · evals.ts:300,314
5副作用只排队不进核心：Executor / Assessor / Outbox 都只排队，领域事件经 options.emit 交给 Runtimeports.ts:55-58, :75-83 · part.ts:64-66
6两个仓储实现语义等价：内存版刻意复制 SQLite 排序；Store.atomic 的 SAVEPOINT 嵌套只是额外保险memory.ts:6-9, :40-41 · store.ts:140-153
7active()/open() 是给轮询用的工作集：SQLite 用生成列 + 部分索引，内存版用 filterstore.ts:30-43, :214, :241 · memory.ts:35, :43
